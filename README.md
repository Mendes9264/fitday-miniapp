# 练食 · 健身与饮食记录原型

开源的个人使用原型：每周四次力量训练模板、训练后补记、餐食文字拆解、热量范围与营养素、可选的每日身体数据及趋势图。记录保存在当前设备。

## 开源与隐私

源代码采用 [MIT 许可证](LICENSE)。项目不附带个人餐食、训练记录或 API Key；这些数据只保存在各设备的应用本地存储中，导出的 JSON 备份也不会自动上传。大模型功能需要使用者自行配置服务商接口和 Key。仓库不包含构建好的 APK，按下文说明可自行构建调试安装包。

## 打开原型

电脑安装 Node.js 后，在项目目录运行 `npm start`，电脑浏览器打开 `http://127.0.0.1:5177/`。手机与电脑连同一个 Wi-Fi 时，运行 `npm run start:lan`，在手机浏览器打开终端显示的完整链接。手机和电脑各自保存记录，互不自动同步。服务重启后，手机访问链接中的一次性访问码会更新。

桌面调试模型接口时请用 `npm start` 打开本机网页。该模式下，网页通过本机服务向模型接口发送请求，避免浏览器跨域限制；本机服务不记录或保存 API Key。若接口返回 HTTP 错误，页面会显示服务商返回的具体原因，并隐藏错误文本中可能出现的 Key。网页与安卓 App 的本地设置各自独立，需要在桌面网页重新填写接口设置。

在“记一餐”加入目录菜后，点“调整食材与用油”可以修改这一份各食材的估计克数；用油按油壶 1 喷约 1 克输入。修改后的配方会随餐食记录保存，且替换原示例配方计算，避免重复计入油。少量盐、酱油、醋和干香料的热量可忽略；糖、淀粉和含油酱料需要按实际用量考虑。目录配方依然是估计，熟重和分餐比例会带来误差。

“记一餐 → 我的食物库”可新建自定义食物，填写名称、常用份量，以及每 100 克的热量、蛋白质、碳水和脂肪。新建后会保存到本机并加入当前这餐；以后可重复加入，也可修改或删除食物库条目。加入餐食时可调整克数，营养数值按份量换算。已保存的餐食保留加入时的营养数值，不会因食物库后续修改或删除而改变。自定义食物和餐食一起进入 JSON 备份。该功能目前在桌面网页预览版验证，尚未重新打包 APK。

已保存的饮食或训练可在“记录”页找到对应日期后点“修改”，调整内容并保存；点“取消修改”会回到修改前的草稿。饮食记录旁的“复用”会把那一餐带入“记一餐”，可以修改日期和份量后另存为一条新记录；旧照片不会被复制。“记一餐”页也会列出最近常吃的餐食，方便直接复用。

训练记录旁也有“复用”，可将练胸日等历史训练的动作、组数、次数、重量和有氧设置带入新的训练草稿；“训练”页的“常练训练”可直接选用常做的安排。默认记录在今天，也可修改训练日期。请核对本次实际完成的组数、次数、重量及有氧时长，再保存为一条新记录；原训练记录不会改变。复用后的草稿可以增删动作和组数，点“取消复用”可返回普通训练补记。

“记录 → 每周总览”按周一至周日查看本周或前几周的餐食、力量训练、有氧、估算热量、蛋白质及体重变化。可用左右按钮切换周；未记录的日期会显示为未记录，不会当作零摄入。这里的饮食统计只汇总已录入的餐食，热量与蛋白质仍取决于保存时的估算或手填数值。这三项新功能目前只在桌面网页预览版验证，尚未重新打包 APK。

在“记录 → 身体数据”可选日期，按需填写体重、腰围、臂围、胸围、臀围和腿围。每天不必填写，单次也只需填其中一项；同一天重新保存会更新该日数据，留空的指标不会在趋势图中当作 0。点“生成趋势图”后可切换指标查看变化。身体数据会进入本地 JSON 备份；这里的体重记录不会自动修改“个人设置”中的估算用体重。该功能目前只在桌面网页预览版中验证，尚未重新打包 APK。

“训练”页可选择“力量＋有氧”或“仅有氧”，添加快走、爬坡步行、跑步、游泳、骑车、椭圆机、爬楼/登阶机、划船机和跳绳。选择速度或强度，填写实际运动分钟和估算用体重后，页面按 [2024 成人体力活动汇编](https://pacompendium.com/adult-compendium/)的 MET 值计算活动千卡：`(MET - 1) × 体重 kg × 时长小时`。这里扣除静息消耗；它是群体平均值的粗估，不是个人精确测量。力量动作的组数、次数、重量不足以可靠换算成单个动作的热量，因此暂不显示逐动作消耗。有氧记录会保存所用体重、MET 和汇编编号；单独有氧不会推进四天力量模板。

跑步机爬坡步行改为填写机器显示的速度（3.2–5.6 km/h）与坡度（1–15%），页面换算每公里配速，并用 [ACSM 步行代谢公式](https://pmc.ncbi.nlm.nih.gov/articles/PMC3656435/)推算 MET。原汇编中的“中等至较快”爬坡条目没有给出精确速度，不能据此指定配速；跑步机模式使用独立公式，历史记录保留保存当时的计算结果。

## 餐食估算

网页与安卓 App 内置中餐菜肴目录与常用食材。可以搜索菜名，加入后调整实际份量、食材比例和用油。文字拆解无法识别的菜会标为“待估算”；可点“用模型估算”，也可在目录搜索框输入菜名后点“用所选模型估算这道菜”。结果会显示热量范围、营养素、食材假设，以及接口提供时的参考链接；核对后点“加入这餐”或“替换待估算菜品”，再修改实际克数。未加入的结果不会计入本餐。若不联网，仍可搜索目录或手动添加食材。

在“个人设置 → 大模型接口”填写接口地址、模型名及可选 API Key，点“保存接口设置”。支持 Chat Completions 兼容接口、Responses 接口和自定义 JSON 请求体、请求头、鉴权方式、响应路径；后者适用于格式不同但可用普通 JSON POST 调用的服务。接口地址和模型配置保存在本机；Key 输入后可在当前会话使用，勾选“在本机记住 API Key”并保存后才会留在本机，关闭 App 后仍可使用。“清除 API Key”会同时删除会话和本机保存的 Key。Key 不进入餐食记录和 JSON 备份；若勾选记住，则保存在本设备的应用本地存储中，清除应用数据或卸载应用会删除它。旧 OpenAI 专用 Key 不会自动迁移，需要重新填写。仅主动查询时发送菜名及营养估算指令，不发送照片、个人资料和整餐记录。模型调用可能消耗服务商额度。

是否实际检索网页取决于所选模型和服务商设置。Responses 模式可请求 `web_search` 并要求接口返回可核对来源；Chat Completions 模式可按服务商文档在附加参数中填写搜索开关，例如 `{"enable_search":true}`。未核实网页检索的结果会明确标成模型知识估算，链接也应自行核对。安卓包启用 Capacitor 原生 HTTP 支持来调用外部接口。复杂签名、特殊协议、仅流式返回的服务仍可能需要专门适配。模型给出的营养数值不是具体菜品实测；请核对份量、油量和做法。

## 微信小程序源码

项目含原生微信小程序源码。安装微信开发者工具后导入本目录；`project.config.json` 使用 `touristappid` 供游客模式或模拟器体验。真机预览及发布需要自己的小程序 AppID。

当前环境没有微信开发者工具和 AppID，微信界面仅经过页面逻辑测试，尚未在官方模拟器或真机验证。修改共享逻辑后运行 `npm run sync:core`。

## 安卓 APK 工程

`android/` 是 Capacitor 原生安卓工程，应用界面和本地菜谱已打包进调试 APK。安装后记录和基础估算不需要电脑，也不需要连接本项目的 5177/5178 服务；数据保存在手机应用本地。

构建测试 APK 需要 Android SDK 36 与 JDK 21。安装好之后在本目录运行：

```powershell
npm install
npm run android:apk
```

生成的调试 APK 位于 `android/app/build/outputs/apk/debug/app-debug.apk`。每次修改网页或共享逻辑后运行 `npm run android:sync`，再重新构建。向其他人正式分发时，需要改为签名的发布版 APK，并妥善保存签名密钥。

安卓桌面图标使用 `android-app/icon-source.png`。更换原图后运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/update-launcher-icon.ps1`，再运行 `npm run android:apk`，即可更新各屏幕密度的普通图标和自适应图标。

网页顶部、浏览器标签和微信小程序顶部使用与安卓启动图标相同的白底哑铃图，网页资源为 `web/logo.png`，小程序资源为 `miniprogram/assets/logo.png`。桌面网页预览已更新；安卓安装包仍需以后重新打包才能看到页面顶部的更改。

手机与电脑在同一 Wi-Fi 时，可运行 `npm run start:lan`，把终端显示的 `?access=...` 附在 `http://<电脑局域网地址>:5178/download/fitday.apk` 后下载；安装完成后可关闭电脑服务，内置目录与记录仍可离线使用，AI 搜索需要手机联网。尚未在安卓真机上验证交互、拍照和联网搜索。网页浏览器与 APK 的本地数据各自独立；若要迁移旧网页记录，在网页“个人设置 → 本地数据”导出 JSON 文件，再在 APK 的同一位置导入。导入会替换 APK 内的现有记录，文件无需上传云端。卸载应用或清除应用数据会删除 APK 内的训练和餐食，建议定期导出备份。调试 APK 使用 Android Debug 签名，正式发布时应换为自己的发布签名。

## 原型边界

- 照片仅在本机留档，没有图像识别。
- 已知家常菜按示例食材和用油估算，无法精确还原实际烹饪方式。未知菜名只有在用户核对并加入 AI 搜索结果后才计入热量。
- 饮食建议基于已记录食物、当天训练及个人参考范围；个人设置中的体重只用于粗略参考，身体数据趋势单独记录。
- 没有账号和云同步。清除浏览器站点数据或小程序本地数据会删除相应记录。
